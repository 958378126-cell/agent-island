# Agent Island 开源发布技术方案

版本：发布方案草案 v1（2026-09-28）  
目标：先发布可审查、可自行构建的源码版 `v0.1.0`；可下载的 `.app` 在签名、公证与干净机器安装验证后再提供。

## 1. 发布定位

Agent Island 是 macOS 顶部的多 Agent 任务看板。首版只承诺三件事：显示有证据的当前活动状态；在可靠终态或需要人工处理时提醒；让用户看清每条信息来自官方接口、本机只读记录，还是仅有进程存在的弱信号。它不替用户批准操作，也不声称能读取所有 Agent 的全部桌面任务。

当前公开包的 `AgentIslandCore` 已通过本机 Release 构建、回归检查和 `agent-island-selftest`；它验证状态契约，但不等同于完整桌面应用已接通。公开发布前尚有隐私清理、路径迁移、状态语义、连接器隔离、授权与安装验证等门槛。宣传页使用“核心包可构建 · UI 接入中”，正式发布时才改为下载或仓库链接。

### 首版能力边界

| 来源 | 首版展示策略 | 公开说明 |
|---|---|---|
| Codex 桌面版 / CLI | 本机会话记录只读观察；受控 CLI 可由 wrapper 上报 | 标为“本地只读”或“手工上报”；不宣称覆盖桌面版全部实时回合 |
| WorkBuddy | 本地会话数据库优先，日志回退 | 标为“本地只读”；数据库结构随客户端升级可能变化 |
| AutoClaw | 本地会话与终态记录只读观察 | 标为“本地只读”；须有真实任务全生命周期验收记录 |
| 豆包 | 聊天存储写入活动推断 | 只能标“活动推断”，不能称任务级运行状态或成功结果 |
| 自定义 Agent | HTTP JSON、本地 JSONL、命令 JSONL | 状态由接入方提供，UI 显示连接器来源与同步时间 |
| Kimi / 千问样例 | 官方查询接口的独立适配器 | Kimi 托管会话与千问 Response ID 各有自己的任务范围，均不等于本机桌面任务总表 |

## 2. 对外数据与状态契约

### 2.1 统一任务

内部唯一键采用 `source + source_instance + native_task_id`。一个会话中的多个回合应有不同 ID；来源没有任务级 ID 时，明确标注“会话级”。事件至少含 `schema_version`、稳定 ID、标题、状态、`observed_at`、`updated_at`、`status_evidence` 与 `source_health`。所有可选值在文档中列出，未知原生状态保留供诊断，不自动归为“运行中”或“成功”。

### 2.2 状态机

| 统一状态 | 用户文案 | 可以由什么证据进入 | 提醒规则 |
|---|---|---|---|
| `queued` | 排队中 | 原生排队 / 规划状态 | 不提醒 |
| `running` | 运行中 | 原生运行事件；本地记录的活动回合 | 不提醒 |
| `blocked` | 等你确认 | 明确等待输入、审批或授权 | 每次从其他状态进入时提醒一次 |
| `succeeded` | 已完成 | 明确成功终态或受控命令退出码 0 | 每个任务终态只通知一次 |
| `failed` | 失败了 | 明确失败终态或受控命令非零退出码 | 每个任务终态只通知一次 |
| `canceled` | 已取消 | 明确取消事件 | 不当作失败；可单独记录 |
| `unknown` | 状态待确认 | 来源断连、超时、旧快照、未知原生状态 | 只提示同步异常，不提示任务结束 |

状态与来源健康分开：`connected / stale / permission_required / unsupported / error`。进程消失、文件停止写入、轮询失败都不能生成 `succeeded`。历史任务初次导入不得补发通知。修复现有映射中 `cancelled/canceled/aborted/stopped → failed`、`terminated → done` 与 WorkBuddy `idle → running` 的混淆；终态须按厂商原义逐项映射。

### 2.3 页面中的颜色与主题素材

排队紫 `#A78BFA`、运行青 `#22D3EE`、等确认黄 `#FBBF24`、完成绿 `#4ADE80`、失败红 `#F87171`。颜色从不单独传达语义，始终配文字与图形；已取消用中性灰，失联用虚线与“同步中断”文字。主题插画只辅助识别，不代替状态文字；第三方主题必须由使用者自行提供授权。

## 3. 需要完成的工程改造

### P0：形成可公开的干净仓库

1. 在实际应用源码目录建立 Git 仓库，明确根目录。只收录 `Package.swift`、`Sources/`、`Scripts/`、`adapters/`、示例配置、文档与已获授权的素材。
2. `.gitignore` 排除 `.build/`、`dist/`、`.DS_Store`、运行日志、临时目录、冲突备份、实际 `agents.json`、令牌文件、真实 `data/tasks.jsonl`。先用 `git status --short` 和 `git ls-files` 审核拟公开文件，再做提交。
3. 将当前任务记录移出源码，提供 `examples/tasks.example.jsonl`，只含虚构标题与 ID。`--selftest` 使用独立 fixture，不依赖用户真实任务文件。公开前扫描整个 Git 历史与最终提交中的密钥、路径、任务标题及日志。
4. 公开仓库只放中性默认主题和主题模板。任何第三方主题的图片、名称和 Logo 均由使用者自行导入并自行提供授权证明，不能从“图片在本机”推定可再分发。
5. README 改为从任意克隆目录构建；删掉本机桌面快捷方式、旧工单与未完成验收的对外叙述。提供真实的 Agent 支持矩阵和隐私说明。

**通过门槛：**全新克隆无私人路径、实际任务、凭证、日志、构建产物；`git ls-files` 可逐项解释；素材与代码授权已明确。

### P1：去本机化与状态可信度

1. 默认运行数据放在 `~/Library/Application Support/AgentIsland/`；仓库里的样例数据只在显式 Demo 模式载入。`AGENT_ISLAND_TASKS` 继续保留为高级覆盖项，wrapper 与 App 共用同一可配置路径。
2. wrapper 使用安全的 JSON 序列化生成事件，稳定 ID 不仅靠秒级时间戳；空命令、特殊字符标题、进程被信号终止均有明确结果。
3. 各适配器输出来源、证据等级、最近同步时间和健康状态。旧运行快照过期时降为 `unknown`，而非长期“运行中”；连接失败不能显示成“暂无任务”。
4. 连接器采用每源独立异步轮询、硬超时、取消、输出大小限制和错误隔离。当前命令连接器在 `waitUntilExit()` 前没有并行排空 stdout/stderr，遇到大量输出可卡住；修复后增加大输出与永不退出命令的回归测试。HTTP 响应与 JSONL 文件也设大小上限。
5. 官方 token 仅从环境变量或系统安全存储读取。带 token 的 HTTP 连接只允许 HTTPS 或明确的本机回环地址；重定向不得把授权头送到其他主机。命令连接器的“执行本机程序”能力在 UI 中明示。

**通过门槛：**无虚假成功/失败提醒；断连有可见状态；一个适配器卡死或返回坏数据不会拖住胶囊和其他来源。

### P2：复现、打包与质量门槛

1. 把内置自检拆成可在干净仓库运行的 fixture 测试，以及每个 Agent 的脱敏集成样本；覆盖开始→运行→等待确认→恢复→成功/失败/取消、重复事件、重启与断连。
2. 修复 Swift 6 actor 隔离警告；构建和测试输出无新警告。CI 在 macOS 上跑 `swift build -c release`、测试、示例配置解析和敏感文件检查。
3. 干净用户账户验收：首次安装、无 Agent、只有一个 Agent、并行任务、通知权限被拒、多显示器变化、Agent 升级、网络断开、应用重启。保留一份脱敏验收记录。
4. `Scripts/make-app.sh` 的 bundle ID、版本号与资源复制逻辑改为可维护配置。源码发布可先提供构建步骤；若附 `.app`，需独立完成签名、公证、升级与回滚验证。
5. README 说明最低 macOS 版本、Apple Silicon 范围、权限用途、从源码构建、连接器示例、来源局限、卸载与数据删除方法。`CHANGELOG.md` 记录已知限制。

**通过门槛：**干净克隆构建和自检通过；至少一条真实任务完成完整生命周期的对照；所有公开声称均能在验收记录中找到证据。

## 4. 建议仓库结构

```text
AgentIsland/
├── Package.swift
├── Sources/AgentIsland/
├── Scripts/
├── adapters/
├── config/*.example.json
├── examples/tasks.example.jsonl
├── docs/CONNECTORS.md
├── docs/SUPPORT_MATRIX.md
├── site/                 # 本方案附带的 HTML 介绍页
├── README.md
├── LICENSE
├── ASSETS_LICENSE.md
├── CHANGELOG.md
└── .gitignore
```

`site/` 可直接作为静态网页发布。页面中的演示任务均为虚构数据；上线前填入实际仓库链接，不展示用户真实任务标题、会话 ID、密钥、个人路径或截图。

## 5. 发布顺序与最终检查

| 阶段 | 交付物 | 结束条件 |
|---|---|---|
| A 清理 | 干净仓库、样例数据、授权文件、可复现 README | 拟提交文件逐项审核通过 |
| B 正确性 | 完整状态机、健康状态、连接器超时/限流 | 关键回归测试和真实任务对照通过 |
| C 公测 | 源码 `v0.1.0`、支持矩阵、HTML 介绍页 | 干净克隆可用，已知限制公开 |
| D 二进制 | 签名/公证 `.app` 与安装说明 | 新账户安装、升级、卸载均通过 |

公开按钮的最后一道门：`git status` 干净、敏感扫描无命中、图片授权与许可证确认、CI 全绿、发布文案与支持矩阵一致。上述条件不齐时可继续内部试用，不把演示或弱信号写成已验证的实时任务能力。
